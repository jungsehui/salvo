바뀌었다: 정식 채널로 `npx vsce publish --packagePath salvo-0.1.1.vsix`
(`--pre-release` 플래그는 pre-release로 패키징한 vsix에만 쓸 수 있어서 실패했다).

## 무엇을 했고 어디까지 됐나

스펙 `docs/superpowers/specs/2026-10-07-http-core-design.md`, 플랜
`docs/superpowers/plans/2026-10-07-http-core.md`(6개 태스크)를 SDD로 구현했다.
태스크마다 리뷰와 수정 라운드를 거쳤고, 브랜치 전체 최종 리뷰와 수정 웨이브까지
끝났다. 브랜치는 worktree `.worktrees/http-core`에 있고 아직 main에 머지하지 않았다.

| 영역 | 내용 |
|---|---|
| 파일 모양 | `operation`이 없는 request는 HTTP. 스키마는 `oneOf`, 파서는 `operation` 유무로 가지를 골라 그 가지 오류만 보여 준다 |
| 치환 | `body.json` 안에서 값 전체가 `{{var}}` 하나면 타입 유지. `null`은 헤더, 쿼리, form 필드, JSON 속성을 생략(배열 원소는 유지) |
| 인증과 가림 | Basic은 UTF-8 base64. 시크릿 원문, URL 인코딩형, JSON 이스케이프형, Basic 자격 증명을 결과와 리포트에서 가린다 |
| URL 검사 | 치환 뒤 절대 http/https URL이 아니면 보내기 전에 케이스 오류 |
| 비주얼 에디터 | HTTP 패널(메서드 선택, URL, 쿼리, 헤더, Basic, JSON/text/form 바디). JSON 바디 편집은 바뀐 항목만 다시 쓰고 키 순서를 따른다 |
| 예제와 문서 | httpbin 예제 2개, 0.2.0, CHANGELOG, README "REST over HTTP", architecture 결정 11 |

## 기각된 가설

- "JSON 바디 전체 교체로 충분하다"(플랜 원안): 손대지 않은 `10.0`과 바디 안 주석이 사라졌다. 잎 단위 병합으로 바꿨다.
- "URL 인코딩형까지 가리면 충분하다": 따옴표나 백슬래시가 든 시크릿은 JSON 바디에서 이스케이프형으로 샌다. 최종 리뷰에서 발견해 고쳤다.

## 건드리면 안 되는 것과 이유

- 테스트 파일은 스펙이다. 새 동작은 새 테스트 파일로 고정했다.
- `run-controller.ts`의 `seen`에 넣는 파생형(URL 인코딩, JSON 이스케이프): 빼면 시크릿이 서버 에코와 단언 상세로 샌다.
- 무거운 검증은 `PATH=<node24> memguard -- <명령>`으로 하나씩. 셸 훅이 `&&` 체인을 막는다.
