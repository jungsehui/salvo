## 구현에서 플랜과 달라진 것 (전부 리뷰에서 나온 판단)

- 폼은 정상 파일을 깨뜨리는 편집을 거절한다. 파일이 스키마 검증에 실패하는 동안
  GUI는 읽기 전용이다(`architecture.md` 결정 9 구현 메모).
- 편집 요청은 큐로 하나씩 처리한다. 실행은 문서당 하나만 돈다. 환경을 바꾸면
  열린 모든 패널이 새 스냅샷을 받는다.
- yaml 직렬화는 `lineWidth: 0`이다. 관련 없는 긴 줄을 다시 접지 않는다. CRLF
  파일은 줄바꿈을 유지한다.
- CodeMirror 진단 밑줄은 CSP에 막히는 `data:` SVG 대신 `text-decoration`으로
  그린다. 색은 전부 VS Code 테마 변수에서 온다.
- `tests/core/no-vscode-import.test.ts`는 그대로 두고 넓힌 가드는
  `tests/core/module-purity.test.ts`에 새로 썼다(기존 테스트 수정 금지 규칙).

## 기각된 가설 (같은 길을 다시 파지 않게)

- `forceLinting`으로 스키마 상태 변화 후 재검사: 대기 중인 검사가 있을 때만
  동작한다(`@codemirror/lint` `force()`가 `this.set`을 본다). `StateEffect` +
  `needsRefresh`가 맞다.
- "스키마가 깨진 파일도 폼으로 고칠 수 있게": 화면은 마지막 정상 모델을 보여
  주므로 경로 기반 편집이 다른 케이스에 들어갈 수 있다. 읽기 전용이 맞다.

## 남은 작업

1. **0.1.1 배포 전 F5 확인(사람).** 헤드리스로 못 돌린 유일한 항목이다.
   quickstart의 `salvo.yaml`에는 스키마 소스가 없어서 그대로는 자동완성과
   진단이 꺼져 있다(`schema: none`). 확인하는 동안만 아래 두 줄을 넣는다
   (커밋하지 않는다. 공개 데모 API는 introspection을 허용한다, 2026-10-02 확인).
   ```yaml
   schema:
     url: https://countries.trevorblades.com/graphql
   ```
   그다음 `examples/quickstart/countries.salvo`를 열고
   `Salvo: Open Visual Editor`를 실행해 다음을 본다.
   - 툴바가 `schema: ready`를 보여 준다.
   - Run all cases를 누르면 두 점이 초록이 된다.
   - URL이나 케이스 이름을 고치면 옆의 텍스트 에디터에 작은 diff가 생긴다.
   - 쿼리에 없는 필드를 쓰면 물결 밑줄이 보이고, 필드 이름에서 자동완성이 뜬다.
   - 입력 중 Cmd+S를 누르면 입력이 파일에 들어간다. 저장이 먼저 끝나면
     문서가 다시 dirty가 되어 한 번 더 저장해야 할 수 있다(순서 미확인).
2. **배포(사람).** `npx vsce publish --pre-release` 또는 `salvo-0.1.1.vsix` 업로드.

## 건드리면 안 되는 것과 이유

- `tests/host/webview-html.test.ts`의 CSP 문자열: 보안 경계 자체다. CSP를 넓히지
  말고 번들 쪽을 맞춘다.
- `src/webview/**`, `src/shared/**`에서 `yaml`, `graphql`, `node:*` import 금지:
  webview는 CORS와 시크릿 경계 밖이다.
- 무거운 검증은 `memguard -- <명령>`으로 한 번에 하나씩 돌린다. 셸 훅이 `&&`로
  묶은 무거운 명령을 막는다. `test:vscode`는 Node 22 이상이 필요하다.
